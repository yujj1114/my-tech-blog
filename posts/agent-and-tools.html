Agent 是什么？从「工具调用」说起

2026年11月5日·约 10 分钟#AI#Agent#学习笔记

理解 Agent，最好的起点是 Tool Calling（工具调用）。普通对话里模型只能说话；有了工具调用，它可以「决定」去执行一个函数。我用一个查天气的小例子入门，结果第一次就写出了一个死循环，把额度烧掉了一截。

一个最小的例子

把查天气函数 get_weather(city) 的定义交给模型。用户问「今天北京热不热」，模型不再瞎编，而是返回结构化请求：函数名 + 参数 {"city": "北京"}。程序真正执行函数，把结果发回去，模型再生成自然语言回答。

关键在于：模型只负责「决定调什么」，真正执行的是你的代码。这一点想通了，Agent 就没那么神秘了。

我的第一个死循环

我把「调用工具 → 拿结果 → 再问模型」写成了 while True。有一次工具返回了错误格式，模型看不懂，又调了一次，还是错误……程序就这么转了 40 多步，每步都在烧 token。等我回过神来，那天的免费额度已经见底。

MAX_STEPS = 6  # 硬性上限，绝不能省
for step in range(MAX_STEPS):
    resp = llm.step(messages)
    if resp.tool_call is None:
        return resp.text          # 模型认为任务完成
    result = validate_and_run(resp.tool_call)  # 先校验参数
    messages.append(tool_result(result))

可靠性靠工程，不靠自觉

从那以后，我给每个 Agent 循环都上了三道保险：最大步数（防死循环）、参数校验（模型可能传错类型、漏必填项）、单步超时（工具卡住不能拖死整个流程）。模型会调错工具、会传错参数，这些都不是 bug，是常态。

它和工作流有什么区别

工作流的路径是人写死的：A 之后一定 B。Agent 的路径是模型动态决定的：它可能先查天气再查交通，也可能判断不需要查。自由度更高，代价就是不确定性更大——所以才需要上面那些工程约束兜底。
