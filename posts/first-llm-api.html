第一次调用大模型 API：一个 Hello World 的完整记录

2026年11月14日·约 9 分钟#AI#API#学习笔记
本文目录

第一次调用大模型 API，代码本身只有十几行，真正花时间的是代码之外的东西。这篇把那三个晚上踩的坑完整记一遍。

先说最惊险的一个坑：Key 差点泄露

我图省事，把 key 直接写在了脚本第一行，跑通后顺手 git add .。提交前最后一秒瞥了一眼 diff，冷汗都下来了。key 永远不要写进代码，更不要进仓库——哪怕只是本地练习。改成环境变量读取，是底线：

import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])
resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "你好"}],
    timeout=20
)
print(resp.choices[0].message.content)

后来我才知道，Github 上有自动扫描泄露 key 的机器人，裸奔的 key 平均几十分钟就会被扫走刷爆。幸好那次没提交。

三个让我卡住的错误

401：key 写错了，或者忘了换环境变量——我那次是多复制了一个空格。429：请求太快触发限流，批量跑的时候一连串报错，得加指数退避重试。context length exceeded：一次性塞太多内容，被上下文窗口挡回来。

还有一个更隐蔽的：messages 里系统指令该用 system role，我写成了 user，结果模型偶尔「忘了人设」，输出飘忽不定。排查了半小时才发现是这一行。

看懂返回结构，才知道花了多少钱

跑通之后我打印了完整的 resp.usage：prompt_tokens、completion_tokens、total_tokens 三个数字。那一瞬间才把「聊天」和「计费」对上号——原来每一次对话都是按 token 真金白银算的。养成看 usage 的习惯很重要，后来优化成本全靠它。

Hello World 只是起点。把 key 管好、把错误码认全、把 token 盯住，起点才算走稳。
