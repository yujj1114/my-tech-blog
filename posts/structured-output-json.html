让模型稳定输出 JSON，我踩了格式解析的四个坑

2026年11月15日·约 9 分钟#AI#Prompt#实践
本文目录
  • 四个真实的翻车现场
  • 正确的解法：用官方结构化输出能力

做 AI 应用绕不开一件事：把模型的自然语言输出变成程序能吃的结构化数据。我最早的解法就是在 prompt 末尾加一句「只返回 JSON，不要其他内容」——结果这句话被模型当成耳边风。

四个真实的翻车现场

① 输出被 ```json ... ``` 代码块包裹；② 前面加一句「好的，这是结果：」；③ 偶尔漏字段或把数字写成字符串；④ 中文引号、尾随逗号导致 JSON.parse 直接崩。每一种都让我写过临时 replace 去擦屁股，越擦越乱。

正确的解法：用官方结构化输出能力

后来我改用模型提供的 JSON Mode / Structured Outputs，直接传一份 JSON Schema，让服务端保证格式合规：

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    response_format={
        "type": "json_schema",
        "json_schema": {"name": "tag", "schema": {
            "type": "object",
            "properties": {
                "sentiment": {"type": "string", "enum": ["pos","neg","neutral"]},
                "tags": {"type": "array", "items": {"type": "string"}}
            },
            "required": ["sentiment", "tags"],
            "additionalProperties": False
        }}
    },
    messages=[...]
)
data = json.loads(resp.choices[0].message.content)  # 稳了

最后一道防线不能省

即便用了 Structured Outputs，我依然在解析后加一层 Pydantic 校验——因为「格式合法」不等于「语义正确」，模型可能填一个合法但错误的值。校验失败就带上错误信息重试一次，两次都不行就记录日志、走人工兜底。

结论：结构化输出 = 服务端 schema 约束 + 应用层校验 + 失败重试，三层缺一不可。靠一句 prompt 祈祷，迟早在半夜被解析异常叫醒。
